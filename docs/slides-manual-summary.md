# สไลด์นำเสนอ: สรุปคู่มือสร้างไกเกอร์เคาน์เตอร์ (Arduino + LND712)

> ที่มา: "คู่มือสร้าง telepole.pdf" ที่อาจารย์มอบให้ (15 หน้า สแกน ไม่มี text layer)
> โจทย์: อาจารย์ให้นำเสนอคู่มือฉบับนี้ เพื่อเช็คว่าเข้าใจเนื้อหาไหม

## 1. ปก — คู่มือสร้างไกเกอร์เคาน์เตอร์ด้วย Arduino และ LND712

- ไกเกอร์เคาน์เตอร์แบบพกพา วัดรังสีอัลฟา เบตา แกมมา และเอกซ์
- ใช้หลอด LND712 ร่วมกับ Arduino Pro Mini 5V
- แสดงผลบนจอ OLED แบบ I2C
- มีการปรับแก้ค่าภูมิหลัง การแปลงหน่วย และการแจ้งเตือนด้วยเสียง
- ควบคุมด้วยปุ่มกด 3 ปุ่ม และส่งข้อมูลผ่าน Bluetooth
- หมายเหตุ: โปรเจกต์จริงกำหนดให้ใช้ Arduino UNO ซึ่งเป็นชิป ATmega328P เดียวกัน โค้ดทั้งหมดใช้ได้โดยไม่ต้องแก้ขา

## 2. ส่วนประกอบฮาร์ดแวร์ 9 รายการ

1. Arduino Pro Mini 5V (16MHz) — บอร์ดไมโครคอนโทรลเลอร์หลัก
2. หลอดไกเกอร์-มืลเลอร์ LND712
3. โมดูลจ่ายแรงดันสูง 400-550V (ควรมีขาสัญญาณ TTL pulse output)
4. จอ OLED 0.96 นิ้ว SSD1306 แบบ I2C
5. โมดูล Bluetooth HC-05 หรือ HC-06
6. ปุ่มกด Tactile Switch 3 ตัว — Select, Up, Down
7. ลำโพงหรือ Buzzer แบบ Passive
8. แบตเตอรี่ Li-ion 3.7V พร้อมโมดูลชาร์จ USB (Power Bank ก็ได้)
9. สายไฟ อุปกรณ์บัดกรี และเบรดบอร์ดสำหรับทดสอบ

## 3. ข้อควรระวังด้านความปลอดภัย

- โมดูลจ่ายแรงดันสูงสร้างแรงดันไฟฟ้าสูงถึง 400-550V
- แรงดันระดับนี้อาจเป็นอันตรายได้
- ต้องใช้ความระมัดระวังขณะต่อวงจร
- ตรวจสอบฉนวนหุ้มทุกจุดให้เรียบร้อยก่อนจ่ายไฟ

## 4. ตารางการเชื่อมต่อขา

| อุปกรณ์ | ขาสัญญาณ | ต่อเข้า Arduino |
|---|---|---|
| โมดูลจ่ายแรงดันสูง | Pulse Output | D2 (Interrupt 0) |
| OLED I2C | SDA | A4 |
| OLED I2C | SCL | A5 |
| ปุ่ม Select | Output | D3 |
| ปุ่ม Up | Output | D4 |
| ปุ่ม Down | Output | D5 |
| Buzzer | Signal | D6 |
| HC-05 | TX to Arduino | D7 (SoftwareSerial) |
| HC-05 | RX from Arduino | D8 (SoftwareSerial) |

- OLED ใช้สาย I2C 4 เส้น: VCC GND SDA SCL
- หากจอเป็นรุ่น 3.3V ควรใช้ Level Shifter สำหรับ SDA/SCL เพราะบอร์ดใช้ลอจิก 5V

## 5. หลักการที่ 1 การนับพัลส์ + ที่ 2 การคำนวณ CPM

**การนับพัลส์**

- หลอด LND712 สร้างพัลส์แรงดันสั้น ๆ ทุกครั้งที่อนุภาครังสีผ่านเข้าไป
- โมดูลจ่ายแรงดันสูงปรับพัลส์ให้เป็นสัญญาณ TTL 0-5V ส่งเข้าขา D2
- ใช้ interrupt เพื่อตรวจจับและนับอย่างแม่นยำ

**การคำนวณ CPM**

- CPM = Counts Per Minute จำนวนพัลส์ที่เกิดใน 1 นาที
- สูตร: `CPM = (จำนวนพัลส์ใน T วินาที) x (60 / T)`
- คู่มือใช้วิธีสุ่มตัวอย่าง 10 วินาทีแล้วคูณ 6 เพื่อให้แสดงผลเร็วขึ้น
- ตั้ง `SAMPLE_TIME = 10000` มิลลิวินาที

## 6. หลักการที่ 3 Conversion Factor

- หลอดไกเกอร์แต่ละรุ่นมีค่าไม่เท่ากัน
- คู่มือระบุค่าที่นิยมใช้กับ LND712 ไว้ 3 ค่า:
  - **0.00833** — ใช้ในโปรเจกต์ Geiger Counter บน ESP32 ของ danjulio
  - **0.00926** — เท่ากับ 108 CPM ต่อ 1 uSv/h พบในเอกสารอ้างอิงบางแหล่ง
  - **0.00233** — ตามตาราง Conversion Factors บางชุด
- คู่มือเลือก 0.00833 เป็นค่าเริ่มต้น ปรับเปลี่ยนได้ผ่านปุ่มตั้งค่า
- สูตร: `Dose (uSv/h) = CPM x Conversion_Factor`

## 7. หลักการที่ 4 Background Correction + ที่ 5 การแจ้งเตือน

**Background Correction**

- ค่ารังสีพื้นหลังมีประมาณ 15-30 CPM ขึ้นอยู่กับสถานที่
- สูตร: `Adjusted_CPM = CPM - Background_CPM`
- หากติดลบ ให้แสดงผลเป็น 0 CPM และ 0.00 uSv/h
- ค่าเริ่มต้นในโค้ดคือ 20 CPM

**การแจ้งเตือน**

- เมื่อ Dose rate สูงเกิน Alert Threshold ที่ตั้งไว้ Arduino ส่งสัญญาณไปที่ Buzzer
- กำหนดความถี่และระยะเวลาการติดต่อกันได้
- ค่าเริ่มต้นของ Alert Threshold คือ 1.0 uSv/h

## 8. ไลบรารีและค่าคงที่หลัก

**ไลบรารีที่ต้องติดตั้งใน Arduino IDE**

- Adafruit SSD1306 — สำหรับจอ OLED
- Adafruit GFX — ฟังก์ชันกราฟิกสำหรับจอ
- SoftwareSerial — สำหรับ Bluetooth (มีมากับ Arduino IDE แล้ว)

**ค่าคงที่**

| ค่าคงที่ | ค่า | ความหมาย |
|---|---|---|
| `SAMPLE_TIME` | 10000 ms | เก็บตัวอย่างทุก 10 วินาที |
| `MULTIPLIER` | 60000 / SAMPLE_TIME | เปลี่ยน CPS เป็น CPM |
| `DEFAULT_CONV_FACTOR` | 0.00833 | Conversion Factor ของ LND712 |
| `DEFAULT_BACKGROUND` | 20.0 CPM | ค่ารังสีพื้นหลังเริ่มต้น |
| `DEFAULT_ALERT_THRESHOLD` | 1.0 uSv/h | เกณฑ์แจ้งเตือน |
| `debounceDelay` | 200 ms | กันการกระเด้งของปุ่ม |

- `pulseCount` ประกาศเป็น `volatile` เพราะถูกแก้ค่าจากฟังก์ชัน interrupt

## 9. โค้ด: countPulse() และ readButton()

- `countPulse()` เป็นฟังก์ชัน Interrupt ทำงานทุกครั้งที่เกิดพัลส์จากหลอดไกเกอร์
- ภายในมีคำสั่งเดียวคือ `pulseCount++`
- `readButton(int pin)` อ่านสถานะปุ่มพร้อม debounce
- สมมติปุ่มต่อแบบ Active Low คือกดแล้วได้ LOW จึงเช็ค `digitalRead(pin) == LOW`
- เช็คต่อว่า `millis() - lastButtonTime > debounceDelay` หรือไม่
- ผ่านทั้งสองเงื่อนไข บันทึกเวลาแล้วคืนค่า 1 ไม่อย่างนั้นคืน 0

## 10. โค้ด: triggerAlert() updateDisplay() sendBluetoothData()

**triggerAlert()**

- ทำงานเมื่อ `alertActive` ยังเป็นเท็จเท่านั้น
- ตั้ง `alertActive = true` บันทึกเวลา แล้วสั่ง `tone(BUZZER_PIN, 2000, 500)`
- การเช็ค `alertActive` ก่อนกันไม่ให้เสียงดังซ้ำทุกรอบลูป

**updateDisplay()**

- เคลียร์จอ ตั้งขนาดตัวอักษร สี และตำแหน่งเคอร์เซอร์
- แสดง CPM, Dose (uSv/h), Alert และ Conv บนหน้าเดียว
- ถ้า `menuMode != 0` แสดงข้อความ "Menu Mode:" ต่อท้ายตามโหมดที่เลือก

**sendBluetoothData()**

- สร้าง `buffer` ขนาด 50 ตัวอักษร
- ใช้ `snprintf` แทน `sprintf` เพื่อจำกัดความยาว กันข้อมูลล้นออกนอก buffer
- ส่งออกด้วย `bluetooth.print(buffer)`

## 11. โค้ด: handleMenu() ระบบเมนู 4 โหมด

- กดปุ่ม Select เปลี่ยนโหมดแบบวนกลับ: `menuMode = (menuMode + 1) % 4`
- โหมด 0 — หน้าหลักแสดงค่าปกติ
- โหมด 1 — แก้ไข Conversion Factor ปรับครั้งละ 0.0001
- โหมด 2 — แก้ไข Background ปรับครั้งละ 1.0 CPM
- โหมด 3 — แก้ไข Alert Threshold ปรับครั้งละ 0.1
- ทุกโหมดมีเงื่อนไขกันค่าติดลบ คือลดได้เฉพาะเมื่อค่าปัจจุบันมากกว่าศูนย์
- มี `delay(200)` หลังกด Select เพื่อป้องกันการกดซ้ำ

## 12. โค้ด: setup() การเตรียมครั้งแรก

- `Serial.begin(9600)` สำหรับ Serial Monitor ไว้ดีบัก
- `bluetooth.begin(9600)` — baud rate มาตรฐานของ HC-05
- เริ่มจอ OLED ถ้าไม่สำเร็จจะพิมพ์ "SSD1306 allocation failed" แล้วหยุดด้วย `for(;;)`
- `pinMode`: GEIGER_PIN เป็น INPUT, ปุ่มทั้งสามเป็น INPUT_PULLUP, BUZZER เป็น OUTPUT
- `attachInterrupt(digitalPinToInterrupt(GEIGER_PIN), countPulse, RISING)`
- แสดงข้อความ "Geiger Counter" และ "LND712 Ready" แล้ว `delay(2000)`

## 13. โค้ด: loop() หัวใจของโปรแกรม

- เรียก `handleMenu()` ทุกรอบเพื่อให้ปุ่มตอบสนองไว
- ทุกครบ `SAMPLE_TIME` (10 วินาที) จึงคำนวณใหม่:
  - สั่ง `noInterrupts()` ก่อนอ่าน `pulseCount` เก็บไว้ รีเซ็ตเป็นศูนย์ แล้ว `interrupts()`
  - **เหตุที่ต้องปิด Interrupt ชั่วคราว:** ถ้ามีพัลส์เข้ามาระหว่างอ่านกับรีเซ็ต พัลส์นั้นจะหายไป
  - `cpm = counts * MULTIPLIER`
  - `adjustedCPM = cpm - background` (ถ้าติดลบให้เป็นศูนย์)
  - `doseRate = adjustedCPM * convFactor`
  - ถ้า `doseRate >= alertThreshold` เรียก `triggerAlert()` ไม่งั้น `alertActive = false`
  - เรียก `updateDisplay()` และ `sendBluetoothData()` แล้วรีเซ็ตเวลา
- ท้ายลูปมี `delay(50)` เพื่อให้ปุ่มทำงานได้ทันที

## 14. การรับข้อมูลบนสมาร์ทโฟน

- โค้ดส่งข้อมูลทุก 10 วินาที ในรูปแบบ `cpm=124.00;uSv/h=1.03`
- แอปที่ใช้รับได้: Serial Bluetooth Terminal (Android / iOS), Arduino Bluetooth Data Logger หรือแอปที่พัฒนาเอง
- ขั้นตอน:
  1. จับคู่ Bluetooth กับ HC-05 (รหัสผ่านเริ่มต้น 1234 หรือ 0000)
  2. เปิดแอป Serial Terminal
  3. เลือกเชื่อมต่อกับ HC-05
  4. ข้อมูลแสดงเป็นข้อความทุก 10 วินาที
- หมายเหตุ: HC-06 เป็น Slave-only ใช้โค้ดเดิมได้ แต่ส่งคำสั่งจากมือถือกลับมายัง Arduino ไม่ได้

## 15. ทดสอบ ปรับเทียบ แก้ปัญหา และสรุป

**การทดสอบ**

- ทดสอบทีละส่วน: จอ OLED, ปุ่มกด, Buzzer, Bluetooth แยกกันก่อนต่อรวม
- ตรวจสัญญาณจากหลอดด้วย oscilloscope หรือ multimeter ที่วัดความถี่ได้
- ตั้งแรงดันประมาณ 500V เพราะ LND712 ต้องการช่วง 450-650V
- เก็บสายสัญญาณ Pulse ให้สั้นที่สุด ใช้ตัวต้านทาน pull-down หากจำเป็น

**การปรับเทียบ**

- ควรเทียบกับเครื่องมือมาตรฐานหากมีความจำเป็น
- ตั้งค่า Background โดยวัดในที่ที่ไม่มีแหล่งรังสีเพิ่มเติม 10-15 นาที แล้วเฉลี่ย
- หากค่าสูงกว่า 15-30 CPM มากในที่โล่งแจ้ง แสดงว่ามีสัญญาณรบกวนหรือตั้งค่าผิด

**การจัดการพลังงาน**

- Pro Mini 20-30 mA + จอ ~20 mA + Bluetooth ~30 mA รวม 80-100 mA
- แบต 18650 ขนาด 2000 mAh ใช้ได้ราว 20 ชั่วโมง
- ประหยัดพลังงานได้โดยปิด Bluetooth เมื่อไม่ใช้ หรือใช้โหมด sleep

**การแก้ปัญหาเบื้องต้น**

| ปัญหา | สาเหตุและแนวทางแก้ไข |
|---|---|
| จอ OLED ไม่แสดงผล | ตรวจการเชื่อมต่อ I2C, สแกนหา I2C address ด้วยโค้ด Scanner |
| Bluetooth ไม่เชื่อมต่อ | ตรวจสาย TX/RX และ baud rate (9600) |
| ค่า CPM สูงผิดปกติ | ตรวจสอบสัญญาณรบกวน, ลองเพิ่มตัวกรอง RC filter ที่ขาสัญญาณ |
| เสียงเตือนไม่ดัง | ตรวจสอบขา Buzzer และ polarity (ถ้าใช้ active buzzer) |
